# 编辑器「多开」设计方案与评估

> 目标：把当前"整个应用只能开一个编辑器窗口"的形态，改造成可以同时打开多个编辑器工作区。
> 本文先澄清"多开"的三种形态，给出成本 / 体验 / 风险的量化评估，再给出推荐方案的落地设计。

---

## 1. 结论先行

| 结论 | 说明 |
| --- | --- |
| **推荐方案 A：同进程多窗口（一窗口一文档/目录）** | 改造集中在主进程窗口管理 + IPC 定向，渲染进程几乎零重构，综合成本最低、体验最符合"多开"直觉 |
| 不建议方案 D：进程级多实例 | 只需删掉单实例锁，但内存翻倍、配置/暂存区/终端/AI 日志完全分裂，属于"看似省事实埋坑" |
| 方案 B：单窗口多标签 | 需要把 2500 行 `App.vue` 的单文档状态重构为 Tab 数组，风险最高，建议放到 P2（或不做） |
| **落地节奏**：P0 = 多窗口（约 3~4 人日）→ P1 = 窗口会话记忆与恢复（约 1 人日）→ P2（可选）= 窗口内多标签 |

---

## 2. 现状：为什么现在是"单开"

`electron/main.cjs` 与 `src/App.vue` 中存在大量"全局唯一窗口 / 全局唯一文档"的硬假设，这是本次改造的全部工作面。

| # | 约束点 | 位置 | 多开时会怎样 |
| --- | --- | --- | --- |
| 1 | 主进程只持有一个窗口引用 `let mainWindow = null` | `main.cjs:11` | 无法管理窗口集合，后续窗口互相覆盖引用 |
| 2 | 终端事件只推主窗口 `sendTerminalEvent` | `main.cjs:20-23` | 第二个窗口开终端，输出会跑到第一个窗口 |
| 3 | 系统对话框全部挂在 `mainWindow` | `main.cjs:272/304/315/444/456/800`（`dialog:selectAiFiles` 已正确使用 `BrowserWindow.fromWebContents`） | 从窗口 2 触发"另存为"，弹窗 modal 会锁住窗口 1 |
| 4 | 窗口级 IPC 只作用于主窗口：`window:toggleDevTools` / `window:setTitle` / `window:setModified` | `main.cjs:1077/1089/1096` | 窗口 2 改标题会改到窗口 1；窗口 2 按 F12 打开的是窗口 1 的 DevTools |
| 5 | 启动/外部文件走全局队列 `pendingOpenFiles`，只推给 `mainWindow`；`app:getStartupFiles` 取完即清空 | `main.cjs:26/55-62/1105-1109` | 双击第二个文件时，当前编辑内容会被静默替换；多窗口下队列被"先问先得"抢走 |
| 6 | 主窗口关闭即 `terminal.killAll()` 并关闭 AI 窗口 | `main.cjs:106-112` | 关掉一个窗口会杀掉另一个窗口的终端 |
| 7 | 渲染进程是"单文档状态机"：`content / currentPath / isDirty / fileType / fileOpened` | `App.vue:78-83` | 一个窗口只能承载一个文件 |
| 8 | 工作区状态写在 `localStorage`（共享 origin） | `App.vue:120-311/1639`，如 `md-last-dir`、`md-last-expanded`、`md-recent-dirs`、`md-sidebar-width`、`md-git-panel-visible`；`TerminalPanel.vue:25-27`、`GitPanel.vue:104-106` | 多窗口互相覆盖展开状态、侧边栏宽度、最近目录；后关的窗口决定重启恢复什么 |
| 9 | 暂存区是全局单文件 `resolveScratchPath()` | `main.cjs:700-736` | 两个窗口同时编辑暂存区，互相覆盖，且自动保存（800ms 防抖）会加剧冲突 |
| 10 | 单实例锁 `requestSingleInstanceLock` + `second-instance` 转发 | `main.cjs:223-234` | **这是资产不是负债**：保留它，多窗口 ≠ 多进程 |

## 3. 三种"多开"的形态澄清

| 形态 | 含义 | 内存 | 隔离性 |
| --- | --- | --- | --- |
| **进程级多实例** | 去掉单实例锁，每开一个文件启动一个 App 进程 | 最重（每实例一套 Electron + Node） | 完全隔离，但也完全无法共享配置/会话 |
| **窗口级多开**（推荐） | 同一进程内创建多个 `BrowserWindow`，每窗口一个独立渲染进程 | 中（每窗口 +80~150MB） | 渲染进程天然隔离，主进程统一调度 |
| **标签级多开** | 单窗口内多 Tab，共享一个渲染进程 | 最轻 | 共享 JS 堆，状态需手工隔离 |

## 4. 候选方案评估

评分 1~5（5 最好），权重按本项目当前阶段（单人/小团队、追求可控）设定。

| 维度（权重） | A 多窗口 | B 多标签 | C 混合（多窗口+每窗口多标签） | D 进程级多实例 |
| --- | --- | --- | --- | --- |
| 实现成本（30%） | **4** | 2 | 1 | 5 |
| 用户体验（25%） | **4** | 4 | 5 | 2 |
| 内存/性能（15%） | 3 | **5** | 3 | 1 |
| 状态一致性（15%） | **4** | 3 | 3 | 2 |
| 风险可控（10%） | **4** | 2 | 2 | 2 |
| 可回滚（5%） | **5** | 3 | 2 | 4 |
| **加权总分** | **3.95** | 3.10 | 2.65 | 2.65 |

### A. 多窗口（推荐）

- **优点**
  - 渲染进程天然隔离：每窗口一个 `BrowserWindow`，`App.vue` 的单文档状态机不用动，编辑器 / 预览 / 撤销历史 / 目录树互不影响——**这是最值钱的一点**。
  - 契合 Windows 使用习惯：任务栏 Alt+Tab、Win+←/→ 分屏、多显示器拖放，这是"多开"的核心诉求。
  - 已有先例：AI 对话窗口（`createAiChatWindow`，`main.cjs:120-155`）已验证"同进程多窗口 + hash 路由 + 跨窗口广播"可行；`notifyChatsChanged` 已用 `BrowserWindow.getAllWindows()` 广播，可直接复用。
  - 可增量上线：先只做"新建窗口"，老行为完全保留。
- **代价**
  - 每窗口一个渲染进程，开 5 个窗口约 +400~700MB。
  - 8 处对话框需改为按 `event.sender` 归属窗口。
  - `localStorage` 冲突必须处理（见 5.3）。

### B. 多标签（不推荐作为第一步）

- 必须把 `App.vue` 的 `content/currentPath/isDirty/fileType` 等提升为 `tabs[]`，所有读写点（保存、脏检查、AI 应用、Git 还原、重命名、终端 cwd、导出 HTML…… 约 60+ 处）都要带 `tabId` 维度。
- 编辑器组件（`MarkdownEditor` 内部持有 history / 预览 / 图表渲染，`defineExpose` 暴露 `resetHistory/getSelectionText/replaceSelection`）要么 keep-alive 常驻（内存接近多窗口），要么切换即销毁（丢失光标、滚动位置、撤销历史）。
- 收益主要是"省内存"，而在编辑器场景下，VS Code / Typora 的对照习惯更偏"多窗口 + 分屏"。

### C. 混合

能力最完整，但等于先付 A 的成本再付 B 的成本，且两套状态模型（窗口注册表 + Tab 数组）叠加，维护成本陡增。**建议等 A 上线后按真实反馈再评估**。

### D. 进程级多实例

去掉 `requestSingleInstanceLock` 只需 3 行，但：文件关联（`fileassoc` 写 HKCU，多实例争抢）、暂存区文件、AI 日志按月落盘（并发写冲突）、`images` 目录、终端子进程全部失去统一管控；内存与启动时间线性增长。**只在"跨屏独立会话"强诉求下考虑**，否则明确不做。

## 5. 推荐方案 A 的详细设计

### 5.1 总体架构

```
主进程（唯一）
├─ windowRegistry: Map<windowId, { win, role: 'main'|'ai-chat', filePath, dirPath }>
├─ 路由层：外部文件 → 目标窗口（策略见 5.4）
├─ IPC 定向：所有窗口级操作取 BrowserWindow.fromWebContents(event.sender)
├─ 共享服务：ai / aiChats / aiLogger / git / terminal / scratch / fileassoc（保持单例）
└─ workspace.json（userData）：记录窗口会话，用于重启恢复

渲染进程（每窗口一份，天然隔离）
└─ App.vue 单文档状态机（不动） + windowId 身份 + 状态分区存储
```

### 5.2 主进程改造清单

| # | 改造项 | 改法 |
| --- | --- | --- |
| 1 | **窗口注册表** | 新增 `windows = new Map()`，`createWindow()` 返回 `{ id, win }`；`mainWindow` 降级为"首个/聚焦窗口" |
| 2 | **IPC 定向** | 新增 `winOf(event)` = `BrowserWindow.fromWebContents(event.sender)`；替换 `dialog:*`（6 处硬编码）、`window:setTitle`、`window:setModified`、`window:toggleDevTools` |
| 3 | **终端事件定向** | `terminal.cjs` 会话增加 `ownerId`；`setEventSender` 改为 `(channel, payload, ownerId) => 只推 ownerId 窗口`；`terminal:killAll` 增加按窗口粒度 |
| 4 | **窗口关闭收敛** | `win.on('closed')` 只回收本窗口的终端会话、从注册表摘除；仅当主窗口集合为空时才关 AI 窗口、才 `killAll` |
| 5 | **外部文件路由** | `deliverOpenFiles(paths)` 改为按 5.4 策略选目标窗口；`app:getStartupFiles` 改为"仅首个主窗口可取"，避免后续窗口抢占队列 |
| 6 | **新增 IPC：新建窗口** | `window:new`（Ctrl+Shift+N）：新建空窗口；`window:openFileInNew(filePath)`：从目录树右键「在新窗口打开」 |
| 7 | **菜单** | 「窗口」菜单补充：新建窗口、在前/后窗口间切换、关闭窗口；`role: close` 保持 |
| 8 | **退出语义** | 保持 `window-all-closed → quit`（非 macOS）；`before-quit` 前对所有窗口做脏检查（见 5.5） |
| 9 | **AI 对话窗口** | 并入注册表（`role: 'ai-chat'`），保持"最多一个"约束；`notifyChatsChanged` 逻辑不变 |

### 5.3 渲染进程改造清单

| # | 改造项 | 改法 |
| --- | --- | --- |
| 1 | **窗口身份** | preload 增加 `getWindowId()`（主进程在创建窗口时通过 `?winId=` 或 `additionalArguments` 注入）；`env.d.ts` 补类型 |
| 2 | **每窗口状态隔离** | 把"工作区状态"从 `localStorage` 迁到 **`sessionStorage`**（每个 `BrowserWindow` 的 WebContents 独立）：`md-last-dir`、`md-last-expanded`、`md-last-sidebar`、`md-sidebar-width`、`md-git-panel-visible`、`md-terminal-*`、GitPanel 高度/提交历史 |
| 3 | **跨窗口仍共享的偏好** | 保留 `localStorage`：`md-code-theme`、`md-view-mode`、图床、PlantUML、工具集历史、AI 图表语言 |
| 4 | **最近目录 `md-recent-dirs`** | 保留全局，但改为"读取即合并、写入去重置顶"，多窗口并行打开也不会丢条目 |
| 5 | **暂存区互斥** | 暂存区保持全局单文件。第二个窗口点击「暂存区」时：若已有窗口打开它 → 聚焦该窗口并提示；否则本窗口打开并登记 `scratchOwnerId`；窗口关闭时释放 |
| 6 | **标题** | `updateTitle()` 不变（改造后天然作用于本窗口）；标题建议带序号或目录名以便区分：`文件名 - 目录名 - Markdown 编辑器` |
| 7 | **入口** | 工具栏新增「新建窗口」按钮；目录树右键新增「在新窗口打开」；快捷键 `Ctrl+Shift+N` |

### 5.4 外部文件路由策略（需产品确认，默认推荐 ②）

| 策略 | 行为 | 评价 |
| --- | --- | --- |
| ① 全部在当前窗口打开 | 双击文件 → 覆盖当前编辑内容（现状） | 与现状一致，但"多开"价值最低；**必须配合未保存拦截** |
| ② **按文件去重 + 聚焦** ✅ | 文件已在某窗口打开 → 聚焦该窗口；未打开 → 在当前聚焦窗口打开（有未保存修改时提示"是否在新窗口打开"） | 默认推荐：不产生意外窗口，也不丢内容 |
| ③ 每个文件都开新窗口 | 双击 N 个文件开 N 个窗口 | 最"像多开"，但连点 10 个文件会开 10 个窗口，需配合窗口上限（建议 8）与"文件已打开则复用" |

建议：默认 ②，设置项提供「外部文件始终在新窗口打开」（即 ③）开关；窗口数上限 8，超出时复用最近最少使用的空窗口。

### 5.5 生命周期与数据安全

- **关闭窗口**：有未保存修改时弹「保存 / 放弃 / 取消」（复用 `guardDirty`，`App.vue:422`）。
- **退出应用**：`before-quit` 逐个窗口做脏检查；任一窗口选择"取消"则中断退出。
- **崩溃恢复（P1）**：主进程维护 `workspace.json`（`[{ winId, filePath, dirPath, viewMode, bounds }]`），下次启动按记录重建窗口——这是"关了还能回到原来几个窗口"的关键，成本约 1 人日。

### 5.6 推荐的交互细节

- 新窗口位置：相对当前窗口偏移 `(30, 30)` 级联，避免完全重叠。
- 新窗口继承：代码主题、视图模式、图床配置（全局偏好）；不继承目录树（新窗口默认空状态或沿用上次目录，建议沿用上次目录，降低空窗感）。
- AI 面板 / Git 面板 / 终端：每窗口独立实例；终端工作目录取本窗口目录（与现状 `terminalCwd` 一致）。

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 多窗口内存增长 | 开 5 个窗口 +400~700MB | 窗口数上限 8；非活动窗口不渲染预览（后续可做：失焦时暂停 Mermaid/图表渲染） |
| 同一文件在两窗口同时编辑 | 后保存者覆盖前者 | P0 可只做提示（打开时提示"该文件已在另一窗口打开"）；P1 加主进程文件锁 + 外部变更检测（可复用 `file:stat` 的 mtime） |
| localStorage 迁移遗漏 | 窗口间互相覆盖布局 | 迁移清单见 5.3-2；冒烟时开 2 窗口分别改侧边栏宽度/展开目录，重启验证互不干扰 |
| 终端事件串台 | 输出跑到错误窗口 | 必测项：两窗口各开终端执行 `echo`，验证输出不串 |
| 暂存区互相覆盖 | 内容丢失 | 见 5.3-5 的 owner 锁 |

## 8. 验收清单（冒烟用例）

1. Ctrl+Shift+N 新建窗口 → 新窗口空状态可用，标题正确。
2. 两窗口分别打开 A.md / B.md → 各自编辑保存，互不干扰；各自标题脏标记独立。
3. 窗口 2 触发「另存为」「导出 HTML」「选择图片」 → 对话框 modal 只锁窗口 2。
4. 两窗口各开一个终端 → 命令输出不串台；关闭窗口 1 不影响窗口 2 终端。
5. 窗口 2 按 F12 → 打开的是窗口 2 的 DevTools。
6. 双击关联文件 → 按 5.4 策略路由（默认聚焦已打开该文件的窗口）。
7. 窗口 1 打开暂存区 → 窗口 2 点击「暂存区」→ 聚焦窗口 1 并提示。
8. 两窗口分别调整侧边栏宽度 / 展开不同目录 → 关闭重启后状态互不污染（P1 后可恢复两个窗口）。
9. 窗口 2 有未保存修改时关闭 → 弹出保存确认；取消后窗口保留。
10. 全部窗口关闭 → 应用退出，无残留 shell 子进程。

| 启动 → 新建窗口 | 窗口数 1 → 2，新窗口 `windowInit.id=2`，标题独立 |
| 窗口上限 | 连续新建到第 9 个返回 `最多同时打开 8 个窗口`，窗口数封顶 8 |
| 终端定向 | 两窗口各建终端，`echo` 输出只回传创建它的窗口（互不串台） |
| 暂存区互斥 | 窗口 1 `locked=false`，窗口 2 `locked=true` |
| 关闭拦截 | 脏窗口 `close()` 被拦截（窗口仍存活），答复 `discard` 后才关闭，其余窗口不受影响 |

**已知取舍（已在 P1 解决）**：重启后只恢复首个主窗口（`md-ws-1` 槽位），多窗口完整恢复需要 `workspace.json` 会话记录，即第 5.5 节的 P1。

### 10.2 P1（窗口会话记忆与恢复）

三件事：**会话记忆与重启恢复**、**同一文件多窗口保护**、**退出时的脏检查**（P0 退出会静默丢弃未保存内容）。

**新增机制**

| 机制 | 说明 |
| --- | --- |
| `workspace.json`（userData） | 记录 `{ slotSeq, windows: [{ slot, filePath, dirPath, bounds, maximized, active }] }`；上下文变化 / 移动缩放 / 聚焦时防抖 800ms 落盘，退出前同步落盘 |
| 持久化槽位 `slot` | 跨重启稳定的工作区编号，通过 `additionalArguments` 注入渲染进程；渲染层用 `md-ws-<slot>` 作存储键，**替代 P0 的运行期窗口 id**（id 每次重排会导致状态串位） |
| 文件归属表 `fileOwners` | 同一文件只允许一个窗口登记；第二个窗口打开时主进程推 `app:file-conflict`，可「切换到那个窗口」 |
| 保存前修改时间校验 | 加载 / 保存后记录 mtime（`file:stat`），保存前比对，被改过则提示「覆盖保存 / 取消」，避免静默覆盖 |
| 退出流程 | `before-quit` 发现有脏窗口则 `preventDefault`，逐个窗口确认（复用关闭守卫），任一「取消」即中断退出；全部处理后才 `app.quit()` |

**改动文件**：`electron/main.cjs`（会话读写、`restoreWorkspace`、`fileOwners`、退出流程、`window:focusFile`）、`electron/preload.cjs`（`onFileConflict` / `focusFile` / `onRequestClose` 携带退出上下文）、`src/App.vue`（槽位存储键、冲突提示、mtime 校验、退出文案）、`src/env.d.ts`。

**过程中修掉的关键缺陷**：初版在每个窗口的 `closed` 事件里重写会话，导致「退出时窗口逐个关闭 → 会话被逐次缩减 → 下次只恢复最后一个窗口」。改为退出阶段（`isQuitting` / `quitPending`）不重写，改为退出前同步落盘完整快照。

**冒烟结果**（真实 Electron 进程，两阶段：建立会话 → 重启验证）

| 用例 | 结果 |
| --- | --- |
| 会话落盘 | 正常退出后 `workspace.json` 保留完整 4 窗口会话（含各自目录 / 位置 / 最大化状态） |
| 重启恢复 | 重新启动恢复全部 4 个窗口，`windowInit.dir` 与 `slot` 一一对应 |
| 槽位记忆 | `slot3 → dirA`、`slot4 → dirB`，各窗口 `md-ws-<slot>` 互不覆盖 |
| 文件冲突 | 窗口 2 打开窗口 1 已开的文件时收到冲突通知，可切换到对方窗口 |
| 退出脏检查 | 有未保存修改时 `app.quit()` 被拦截（进程存活），答复 `discard` 后才逐个关闭并退出 |

**已知取舍**

1. 逐个关闭到最后一个窗口再退出时，下次启动恢复的是「最后仍存在的那个窗口」而非被关闭的那些（全部关闭时不做记录，避免下次启动空会话）。
2. 文件冲突只做提示 + 可切换，不强制关闭新窗口；真正的写冲突由「保存前 mtime 校验」兜底。
3. `extractFilePaths` 会把 `electron xxx.js` 的脚本路径也算作待打开文件（仅开发模式冒烟可见，打包后 argv 为真实文件）。
